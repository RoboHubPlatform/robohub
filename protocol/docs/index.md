# robohub-protocol

The RoboHub wire protocol, written once. A board, a gateway and a relay each
generate their payloads from these schemas with `rho protocol generate`; this
module is where the schemas are edited, and the copies every consumer keeps are
written from it.

| Schema | Level | Who generates it |
|---|---|---|
| `common.rho` | both | included by the others: the device and gateway identity, `MessageId`, diagnostics, control, `PowerReading`, `StateReading`, `SensorReading` |
| `link.rho` | L2, board ↔ gateway | a node: `Hello`, `Telemetry` |
| `uplink.rho` | L1, gateway ↔ gateway | a relay: `Announce`, `Reading` |
| `gateway.rho` | both | a gateway, which speaks both levels |

One `MessageId` numbers the whole wire. A message that has a name at each
level is one number: `HELLO` and `ANNOUNCE` are both `0x0101`, `TELEMETRY` and
`READING` both `0x0201`.

`RELAYED` (`0x0013`) is a board's frame carried whole by a relay that holds no
key of the board's: `port(u8) | inner_msg_id(u16) | inner_tx_id(u16) |
inner_payload`, sealed under the relay's own session. Its payload runs to the end
of the frame, so it is written out in `common.rho` rather than declared as a
message; the gateway and the C relays read and write it by hand.

## Changing the protocol

1. Edit the schema here, in `schemas/`.
2. Run `tools/sync.py`. It copies the schemas into every consumer listed in
   `consumers.yml` and runs `rho protocol generate --platform robohub` there, so
   the generated C or Rho is the new protocol's.
3. Build and test each consumer, and commit it with its new copy.

`tools/sync.py --check` changes nothing and exits 1 when a copy or a generated
file is not what the source makes: a schema edited in a consumer, a generated
file edited by hand, or code generated by an older toolchain. A consumer that is
not checked out is passed over.

## Consumers

| Consumer | Carries | Generates |
|---|---|---|
| `robohub-gateway` | all four | Rho, from `gateway.rho`: `src/gateway/wire` |
| `robohub-devices/runtime/device-node`, `nodes/gateway-node` | common, link | C: `src/protocol` |
| `robohub-drivers` gateway examples (relay, relay-host, uplink-host) | all four | C: `src/protocol` |
| `robohub-drivers` repeater and the DS18B20 telemetry node | common, link | C: `src/protocol` |

`consumers.yml` is the list `tools/sync.py` reads: each consumer's path, the
schemas it carries, and what is generated where. A consumer keeps its copy in its
own `schemas/` directory, byte for byte the source's.

This is not an interface an application calls. Applications reach readings
through `robohub.gateway` (see {ref}`robohub-gateway-contract/index`); the wire is
what boards and gateways speak (see {ref}`robohub-gateway/index`).
